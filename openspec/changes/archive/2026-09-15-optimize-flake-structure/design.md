## Context

See `proposal.md` — Why. Current constraints that shape the approach:

- `tofu/defaults.nix` is already the de-facto shared-values hub (domain, subdomains, azure VM, easytier mesh) and is imported by `flake.nix`, `hosts/azure/configuration.nix`, `hosts/azure/substore.nix`, and `hosts/raspi/configuration.nix`. OpenTofu HCL never imports it; it only reads the generated `terraform.tfvars.json`.
- Host files repeat a common block (hardened sshd, admin user, wheel sudo, zsh, common packages, `stateVersion`) that differs only in admin SSH keys and a few deltas.
- The six home-manager files are near-identical; three differ only by username/home directory.
- The flake neither exports modules nor defines `checks`; `specialArgs` and integration module lists are repeated per host, and `hosts/digital-ocean` omits `specialArgs` entirely.
- `hosts/orb/orbstack.nix` and `hosts/orb/incus.nix` are autogenerated-managed and must not be reformatted.

## Goals / Non-Goals

**Goals:**
- One place to change any shared value; hosts declare only deltas.
- Shared modules importable via flake outputs and evaluable by `nix flake check`.
- One nixpkgs instance for integrated home-manager, with overlays declared once.
- Zero behavioral change to any deployed host.

**Non-Goals:**
- Adding new hosts or services, or changing any service behavior.
- Introducing flake-parts or other new flake inputs.
- Relocating `hosts/modules/` or `home-manager/modules/` (paths stay as-is; only how they are imported changes).
- Integrating macbook home-manager into `darwinConfigurations` (standalone `homeConfigurations` are retained by request).
- Managing `hosts/orb/orbstack.nix` / `incus.nix` beyond leaving them untouched.

## Decisions

### D1. Root `defaults.nix`, not `tofu/defaults.nix`
Promote the hub to the repo root. It is consumed by Nix, not OpenTofu, so the `tofu/` prefix was misleading once identity is added. Keep the existing attr names (`domain`, `subdomains`, `azure`, `easytier`) and add `identity.users` and `hosts.<name>` (hostname, role, `adminKeys`). `flake.nix` remaps into `tofuVars`, so `terraform.tfvars.json` and all HCL are unchanged.
*Alternative:* keep the file under `tofu/` and add identity there — rejected, couples non-infra identity to the IaC directory.

### D2. Export modules as flake outputs
Add `nixosModules`, `homeManagerModules`, `darwinModules` = `import` of the existing files under `hosts/modules/` and `home-manager/modules/`. Hosts import `inputs.self.nixosModules.server`, etc. This makes every module independently evaluable and removes depth-dependent relative paths.
*Alternative:* keep relative imports — rejected; not reusable or checkable in isolation.

### D3. Host constructors in `lib/`
`lib/mkNixos.nix` / `lib/mkDarwin.nix` / `lib/mkHome.nix` accept a host name and apply the common module set (`disko.nixosModules.disko`, `home-manager.nixosModules.home-manager`, `sops-nix.nixosModules.sops`) plus `specialArgs = { inputs, defaults, ... }` once. Host files then list only host-specific imports/deltas.
*Alternative:* flake-parts — rejected; adds an input for a small personal flake.
*Alternative:* keep explicit module lists — rejected; that is the current source of drift (digital-ocean lacks `specialArgs`).

### D4. Bases: `base` → `server` → `cloud-vm`
Split shared NixOS logic by concern:
- `hosts/modules/base.nix`: nix settings/experimental-features, gc, `stateVersion` default (parameterized), zsh, common packages, derived `my.isRemote` from the host registry.
- `hosts/modules/server.nix`: hardened sshd, wheel sudo, admin user + root keys sourced from `defaults.hosts.<name>.adminKeys`.
- `hosts/modules/cloud-vm.nix`: grub EFI-removable boot, `useDHCP`.
- `hosts/modules/overlays.nix`: apply `additions`/`modifications`/`unstable-packages` once.
- `hosts/modules/sops-common.nix`: the `SOPS_AGE_SSH_PRIVATE_KEY_FILE` workaround + parameterized `defaultSopsFile`.

`stateVersion` is a **parameter**, not a constant: raspi HM (`25.11`) and digitalocean (`24.05`) keep their values.

### D5. `useGlobalPkgs = true` for integrated home-manager
Removes per-HM `nixpkgs.overlays` in the five integrated profiles so user and system share one nixpkgs. Standalone `homeConfigurations.{luyan@macbook, zly@pascal06}` keep their own overlays (no system to inherit). Standalone profiles are only imported by `flake.nix` and are not integrated into a NixOS system.

### D6. Collapse home-manager files onto `home-manager/modules/base.nix`
`base.nix` holds overlays-config, `programs.home-manager.enable`, `systemd.user.startServices`, `stateVersion` parameter, and the common program imports. Each `home-manager/luyan-*.nix` becomes identity (`home.username`/`homeDirectory` from `defaults`) plus genuine deltas. `programs.neovim` is **kept** in `prelude-linux` (deviation from the original plan): raspi's home-manager profile has no neovim, so removing the system-level enable would drop the editor on raspi.
*Alternative:* generate all HM profiles from the registry — rejected; profiles have real per-host deltas (xcode/ghostty on macbook, sops token on macbook).

### D7. `checks` per system
Add `checks.<system>.<host> = self.nixosConfigurations.<host>.config.system.build.toplevel` for Linux hosts and `self.darwinConfigurations.<host>.system` for macbook. These force full evaluation so `nix flake check` catches drift. Use `--no-build` locally for fast iteration; CI may build. A nixfmt formatting gate was considered and deliberately not added (the repo is not uniformly nixfmt-formatted; a gate would churn unrelated files).
*Alternative:* evaluate-only checks via a `runCommand` — rejected as more machinery for little gain.

### D8. Overlays at system level only
Applied via `hosts/modules/overlays.nix` for every NixOS host; azure/raspi currently duplicate this in `configuration.nix`, and digital-ocean/pascal-cloud-01 have none but need them once base modules are shared.

## Risks / Trade-offs

- **Behavior drift during extraction** → Verify each host with `nixos-rebuild dry-build --flake .#<host>` (and `darwin-rebuild build` for macbook) before and after; diff the evaluated `config` where practical. Land work in the phases below so each is independently revertable.
- **`useGlobalPkgs = true` changes which nixpkgs HM resolves** → Intended and behavior-preserving for overlays already applied at system level; verify no HM-only overlay was relied upon (the three overlays originate in `overlays/default.nix` and are applied system-wide).
- **`checks` build cost** → Full evaluation of every host can be slow; mitigate with `nix flake check --no-build` for local iteration.
- **`stateVersion` unification temptation** → Explicitly kept per host to avoid data-format migrations.
- **Orb autogenerated files** → Left untouched; only `hosts/orb/configuration.nix` is refactored.
- **`initialHashedPassword`/`mutableUsers` differences** (raspi, orb) → Preserved as per-host deltas when extracting the admin user; base module must not force defaults that override them.
- **Collision with active `optimize-singbox-routing`** → That change touches `hosts/azure/substore-templates/*.json` only; this change must not modify those files.

## Migration Plan

Land in five phases, each verified and independently revertable:

1. **Foundation** — add root `defaults.nix` (mirroring current values), `lib/` constructors, and flake module exports. No host behavior change.
2. **NixOS modules** — add `base`/`server`/`cloud-vm`/`overlays`/`sops-common`; migrate azure, pascal-cloud-01, digital-ocean, raspi, orb to them.
3. **Home-manager** — add `home-manager/modules/base.nix`; collapse the six profiles.
4. **Wiring** — switch `flake.nix` to the constructors; set `useGlobalPkgs`; add `checks`.
5. **Cleanup** — remove `hosts/modules/default.nix` and template leftovers, fix the stale `darwin.nix` comment, run nixfmt.

**Rollback:** `git revert` the offending phase commit. No flake input changes are required, so no input bump is needed; OpenTofu state is untouched.
