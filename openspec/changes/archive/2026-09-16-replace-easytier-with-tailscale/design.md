## Context

See `proposal.md` - Why. Current state that shapes the approach:

- The mesh exists in two unrelated forms today: a Linux EasyTier mesh (`azure` relay/exit, `raspi` client) driven by `hosts/modules/my-et-network`, and a client path on the Mac that is *not* an EasyTier node at all — the Mac's sing-box config embeds a WireGuard endpoint pointed at the EasyTier WireGuard portal. That config is generated by sub-store from `hosts/azure/substore-templates/{1.13,1.14}/mac.json` and delivered as a subscription.
- `hosts/azure/substore.nix` already renders the sub-store payloads through `sops.templates`, so a sops placeholder inside the template content is decrypted at activation time.
- The flake pins nixpkgs 26.05 (sing-box 1.13.x). The sing-box `tailscale` endpoint exists since 1.12.0, so both the 1.13 and 1.14 Mac templates can carry it.
- The tofu stack (`tofu/`, azurerm backend) owns the Azure VM *and* the EasyTier NSG ports. `secrets/common.yaml` holds the single EasyTier shared secret for every host.

## Goals / Non-Goals

**Goals:**

- Replace both EasyTier roles with one tagged Tailscale tailnet, keeping EasyTier available but inactive.
- Make the tailnet's policy (ACL, tags, exit approval, DNS) owned by OpenTofu, with node credentials minted there.
- Keep the Mac on a single TUN by using sing-box's userspace endpoint.
- Keep every credential out of git, including the auth key delivered to the Mac.

**Non-Goals:**

- Consuming MagicDNS names inside the sing-box templates (peers are addressed by tailnet address). Adding a `tailscale` DNS server would introduce a fourth resolver class and change `singbox-dns-resolvers`.
- Tailscale SSH, Taildrop, or Funnel in this change.
- Opening an inbound Tailscale transport port on Azure (DERP-only, egress-initiated).
- Migrating `digitalocean`, `pascal-cloud-01`, or `orbstack`.

## Decisions

**Separate `tofu/tailnet/` stack with its own state key.** Tailnet policy is global and changes on a different cadence than the Azure VM; sharing one state would force an `az login` and an Azure provider configure for a policy edit, and would put the VM at risk during a tailnet apply. Alternative: extend the existing `tofu/` state — rejected for coupling and blast radius. Alternative: local state — rejected because the keys live in state and deserve the same remote, backed-up storage as the rest of the infra.

**Provider authenticates from environment variables (OAuth client).** Mirrors the existing `CLOUDFLARE_API_TOKEN` pattern. Alternative: a personal API key in `terraform.tfvars` — rejected as broader-scoped and long-lived; OAuth clients are scoped and revocable.

**Per-node tagged, pre-authorized, reusable auth keys minted by the stack (choice B).** Keeps enrollment reproducible without browser logins and lets tags ride on the key, which removes any device-lookup ordering problem. Alternative: interactive enrollment (choice A) — rejected by the user in favour of hermetic rebuilds. Trade-off accepted below.

**ACL `autoApprovers` is the sole owner of exit-node approval.** `tailscale_device_subnet_routes` requires the device to already exist, which cannot be guaranteed when the node is provisioned by Nix and not by tofu; using both would also trigger the provider's own drift warning. Alternatives rejected because they either fail on first apply or duplicate ownership.

**Mac uses the userspace `tailscale` endpoint; the auth key is injected from sops.** `system_interface` stays off so the endpoint plugs into sing-box's existing routing table — no second `utun`, no route contention. The key is injected by replacing a token in the template content with `config.sops.placeholder."..."` inside `mkSingboxFile`; `sops-install-secrets` substitutes it when `files.json` is rendered. The placeholder has the form `<SOPS:...:PLACEHOLDER>` — no JSON-breaking characters. Alternative: put the key in `mac.json` — rejected (git). Alternative: a native Tailscale client on the Mac — rejected (second TUN + the user's explicit choice).

**A flake app bridges minted keys into sops.** Terraform cannot write sops, so the bridge is unavoidable; making it a flake app keeps it one repeatable command and produces a reviewable encrypted diff. Alternatives: manual copy (error-prone at three keys), or not minting keys in tofu (contradicts "tofu manages the tailnet").

**Both `azure` and `raspi` advertise an exit node; no consumer is opted in.** Matches the prior topology's capability without silently rerouting traffic. `raspi` uses `useRoutingFeatures = "server"` (advertise only), not `"both"`.

**Caddy keeps its public path; only the upstream changes** to `raspi`'s tailnet address, so the external contract (`navi.egrecho47.top` via Cloudflare) is unaffected.

**EasyTier is kept as an opt-in fallback, off by default.** Deleting it is destructive and hard to reverse for a mesh that may still be needed, so the module, its flake registration, `defaults.nix` values, sops secret, tofu vars and NSG rules are all preserved behind one `defaults.nix` boolean. That boolean gates the NixOS service, the sops secret and the tofu rules together. Alternative: delete it outright — rejected by the user. Caddy stays on the tailnet regardless of the flag; the fallback is for reachability, not for the navidrome path.

## Risks / Trade-offs

- [A reusable key leaked via the served subscription or tfstate can enroll a rogue node] → keys mint nodes into role tags that drive exit auto-approval, and rotating the key through the bridge revokes the leaked one; tag-scoped grants remain a follow-up because the managed policy currently preserves allow-all connectivity for parity with the pre-existing tailnet.
- [Minted keys live in OpenTofu state (Azure blob)] → state stays in the same private remote backend; the bridge means sops, not state, is the host-facing source.
- [`raspi` as an exit node is behind NAT and will fall back to DERP] → accepted; throughput is limited and the exit is optional per client.
- [`raspi` already runs sing-box with a TUN; adding `tailscale0` + forwarding may interact with routing/reverse-path/masquerade] → verify `checkReversePath`, route precedence, and NAT after enabling; this is the most likely cutover breakage.
- [EasyTier and Tailscale both define `net.ipv4/ipv6.conf.all.forwarding` at the same module priority (`mkOverride 97`)] → when the fallback is enabled alongside Tailscale the definitions collide on `azure`, so each host sets the shared sysctl with `lib.mkForce` while the fallback is on, breaking the tie without disabling either mesh.
- [The tofu→sops bridge is a manual re-run, not automatic] → documented as part of the deploy sequence; `tofu apply` alone does not update secrets.

## Migration Plan

1. Create `tofu/tailnet/` and the flake apps; obtain the OAuth client credential (manual, once).
2. Apply the tailnet stack (ACL, tags, keys, DNS preference).
3. Run the key bridge; commit the encrypted `secrets/common.yaml` diff.
4. Add `services.tailscale` to `azure` and `raspi`; deploy and confirm both enroll and advertise exit.
5. Update the Mac templates + `substore.nix` injection; confirm the Mac joins and reaches the tailnet.
6. Repoint Caddy's navidrome upstream; verify the public path.
7. Leave EasyTier in place as the disabled fallback (`easytier.enable = false`); its module, secret, tofu vars and NSG rules remain in the tree, ready to re-enable as a unit.

**Rollback**: git revert restores the EasyTier module and host wiring; the EasyTier secret and `tofu.tfstate` are untouched until step 7, so the mesh can be brought back by redeploying. Keep the old public-IP state key and the `my-et-network` secret until the new path is verified stable. A flake input bump is not required (no new flake inputs).
